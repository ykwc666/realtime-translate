## 0.5 术语小抄（后面会反复用）

| 缩写 | 大白话 |
|---|---|
| ASR | 语音识别，把声音转成文字 |
| MT | 机器翻译，把一种文字转成另一种 |
| `mt_ok` | 译文能直接用的比例，分母是全部条目 |
| `given-ASR` | 「假设已经听对了」时译文能用的比例。它把「听错」和「译错」分开算 |
| CER / WER | 字错率 / 词错率。0 = 一字不差，1 = 全错 |
| `postedit` | 译文出来后再做一次规则修补，例如把「右右」改回「对」 |
| TM | 翻译记忆库，整句查表直接给答案，不过模型 |
| `n_utts` | 一句话被切成几段识别 |

## 2. 你的方案，哪三处要改

### 2.1 「按失败句做 postedit/TM A/B」= 重走 `119b526`

你的原话：

> 现在不是「假坏题」，是真意译/漏译。按失败句做 postedit/TM A/B，Dev 同步报，禁止只刷 Test。

**问题是：zh_en 的 7 条「译错」里，3 条根本不是译错。**

```
001  还有QQ。这些东西是在智能手机的普及率很高的。
     hyp: And, these things are very popular on smart phones.
     ref: ...a very high penetration rate amongst smart...
     → 同义改写，判 awkward

021  很好。那我们继续，你
     hyp: Well, good. Let's continue. You.
     → keep going = continue，判 awkward

028  还有一个像叫
     hyp: There's another one called "The"
     → 句子本身没说完，这样译是对的，判 awkward
```

按「失败句」加规则，你会为这 3 条各写一条 postedit。结果是：**Test 涨 3 条，Dev 不一定涨，因为 Dev 那 7 条是另外 7 句话。**

这就是 `119b526` 做过的事——`if "外卖" in src` / `if re.search(r"很宅|会很宅|宅", src)`。它在那批语料上有效，换一批就失效。当时 Test 从 37% 涨到 70%，但其中至少 4 个点是补丁撑的。

**规矩：任何 MT 规则必须按「语法/语义模式」写，不许出现具体名词。**

```python
# 允许：模式
if 句子里只有「程度副词 + 形容词」且无主语 → 补主语

# 不允许：具体词
if "外卖" in src: ...
if re.search(r"很宅|会很宅", src): ...
```

**并且每条规则必须同时在 Test 和 Dev 上验证。只在一个集上有效的，退回。**

### 2.2 en→zh 不该排最后

你把 en→zh 排在「中译英稳住之后」：`Dev en_zh mt_ok 72%、fragment_lost 偏高`。

数字你读得没错（实测 Dev en_zh 71.7%、fragment_lost 8 条 = 13.3%）。但有两个判断要修正：

**① en_zh 的失败比 zh_en 更集中。** Test 的 11 条失败里 8 条在 ≤2 词；zh_en 的 13 条散在 2–33 字。集中块能一次修掉，长尾不能。

**② `fragment_lost` 这个 12 条，没有一条是「切碎了」。** 逐条看：

```
Test 010  Yes.        → あ、イ        n_utts=1   ← 没切，是假名
Test 032  dying       → 三嗯。        n_utts=1   ← 没切，是听错
Dev  009  Ohh, cool.  → 阿克。        n_utts=1   ← 没切，是听错
Dev  028  okay, my    → まい         n_utts=1   ← 没切，是假名
Dev  047  for         → EMPTY        n_utts=0   ← 空识别
Dev  036  Yeah. Yeah. → Yeah撇。     n_utts=1   ← 没切，是噪声
```

**12 条里，11 条 `n_utts=1`、1 条 `n_utts=0`——没有一条 `n_utts>=2`。**

也就是说，**这 12 条里没有一条是被切碎的**。全部是「一句短音频，识别没出来」。把它叫「碎切」会让人去改切分逻辑，方向从一开始就错了。

顺带说一句：`fragment_lost` 的定义是 `cov < 0.8`（`eval_dialogue_mslt.py:319`），量的是**识别覆盖率**，名字却像在说**切分丢句**。这个命名本身就该改，否则每次看报表都会有人误解。

真要修切分，先按 `n_utts>=2` 过滤——现在这个条件是 0 条。

### 2.3 你漏了「尺子不准」这一层

Test 的 24 条失败里，**5 条（21%）不是模型的问题**：

- zh_en 3 条判定器误杀：001（`very popular` vs `penetration rate`）、021（`continue` vs `keep going`）、028（句子本身没说完）
- en_zh 2 条同义不同字：020（`Exactly→准确`）、050（`Ohh→哦…呵呵`）

这不是说「什么都别做、先修尺子」。**en_zh 短句那一刀不依赖尺子**——它的失败是空译文和音译，判定器怎么调都还是错（`右右` 永远不等于 `对`）。

但 **zh→en 的长尾归因必须等尺子定下来**。那 7 条 MT 失败里 3 条是误杀，不先分清，你会把「翻译对了」当成「翻译错了」去归因，越查越偏。

所以真正的顺序是：**第 1 步（en_zh 短句）和第 2 步（尺子）并行，第 3 步（长尾）必须排在第 2 步之后。**
