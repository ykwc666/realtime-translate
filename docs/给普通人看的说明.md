# 这个软件是干什么的？（给普通人看的说明）

不用懂编程也能看懂。下面尽量不讲技术词；实在避不开的，会用大白话解释。

---

## 一句话

这是一个跑在你自己电脑上的 **中英通话翻译助手**：

- 你说中文 → 对方（或你）听到英文；
- 对方说英文 → 你听到中文。

它不靠网上的翻译 App 实时联网（模型都在本机），所以数据和声音主要留在你这台电脑里。

---

## 你可以把它想成什么？

想象开会时旁边坐着一个翻译：

1. 听你把一句话说完；
2. 在脑子里换成另一种语言；
3. 再用嘴巴说出来。

这个软件做的就是这三步，只不过「耳朵」「脑子」「嘴巴」都是电脑程序：

| 人的动作 | 软件在做什么（人话） |
|----------|----------------------|
| 听有没有人在说话 | 判断：现在是静音，还是有人开口了？ |
| 听清你说了啥 | 把声音变成文字（像语音输入法） |
| 翻译 | 把中文换成英文，或反过来 |
| 说出来 | 用合成声音播放出来 |

---

## 它适合什么场景？

比较适合：

- 中英文电话、线上会议，你需要「听懂对方 / 让对方听懂你」；
- 想本地用、少把通话内容丢到网上。

不太适合拿来当：

- 同声传译级「边说边出字、几乎零停顿」（它更偏向：**一句说完再译**）；
- 嘈杂酒吧、严重口音、很长很难的文学朗读——这些会听错，一听错，翻译也会跟着错。

---

## 使用时你会感觉到什么？

正常体验大概是：

1. 你说完一句，停一小会儿；
2. 软件认为「这句说完了」；
3. 过不到一秒（理想情况）到一两秒，耳机里播出译文。

如果感觉「反应慢」，常见原因不是「电脑坏了」，而是：

- 它在等你确定说完（怕你只是换气，还没说完）；
- 或者这句话比较难识别，要多算一会儿。

如果感觉「译得不对」，先问自己：

- 是不是它根本没听清？（字幕/识别文字已经错了）  
  → 听错了，翻译再努力也救不回来。  
- 还是听对了，但中文表达别扭？  
  → 那才是翻译本身的问题。

---

## 两种常见用法（不用记命令）

1. **你对着麦克风说中文**  
   → 软件译成英文播出来（给听英文的人）。

2. **电脑正在播放英文**（会议软件、视频里的人在说）  
   → 软件「偷听」系统声音，译成中文播给你听。  
   （专业说法叫环回；你可以理解成：翻译也戴着耳机听扬声器。）

进阶还有「两边同时开」：你说中文出英文、对方英文出中文。这时要注意：自己的翻译声不要又被录回去，不然会乱套——像两个人对着扩音器互相喊。

---

## 它为什么有时很准、有时很惨？

团队用「自己编的通话短句」测过，可以测得很漂亮。  
后来又用网上公开的英文录音（会议片段、朗读）测了一遍，发现：

- 真实杂乱语音里，**听错、听断**的情况很多；
- 听错之后，翻译分数会很难看；
- 专门为「通话口头禅」准备的小修正，在那种录音里几乎用不上。

所以可以记一句很实在的话：

> **翻译再聪明，也救不了「没听清」。**

这也是为什么后面优化会优先想办法「听得更准」，而不是只改翻译措辞。

## 和市面上翻译软件有什么不一样？

| | 这个项目 | 常见手机翻译 / 会议插件 |
|--|----------|-------------------------|
| 数据去哪 | 主要在你电脑上 | 常常要上传云端 |
| 要不要网 | 模型下好后可本地跑 | 多数要联网 |
| 速度 | 受你电脑快慢影响 | 受网络和服务器影响 |
| 形态 | 更像「研究 + 自用工具」 | 成品 App，按钮更傻瓜 |

它现在更像一台 **自己搭的翻译工作台**，不是包装精美的消费级产品。对开发者来说，好处是能改、能量、能查问题；对普通人来说，上手成本会高一点。

---

## 你如果只想记住三件事

1. **干什么的**：本机中英通话翻译，说完一句再译再播。  
2. **好不好用取决于**：先听清，再翻译；听不清一切白搭。  
3. **它不是魔法**：安静、口齿清楚、句子别太怪，体验会好很多。
