## 2. 要说清的三件事

### 2.1 D 少写了 3 项（不算回归，但要记账）

```

```

为什么不可能是"改坏了"：`git diff` 里所有新增语句只写 `stats.src_raw` / `stats.punct_dropped` / `stats.arbiter_pick`，或 `print`；没有一处分支条件被改。

真正的抖动源在 `app/dual_track.py:632-660`：`[ASR spec start]` 在 `sil >= need` 时把 `self.buf` **快照**一份去做 2pass，命中后 `finalize` 直接用这份快照的结果（`:1227-1234`）。快照多长取决于线程调度，所以同一份音频、同一份代码跑两次，个别 utt 的 `src` 会差几个字。

**读数结论：en_zh 的 asr_err / coverage 噪声地板 ≈ 1 条。** 以后 A/B 只认 ≥2 条的差；1 条以内不许当结论。

任务书 §3 写「027 按 ASR 原文只有 0.04 CER」。实测 **0.3043**（23 字参考 vs 28 字原文；真差异是「土豆丝儿/土豆丝」「把这个…放下去」的语序）。0.04 是我算错了。

### 2.3 两个读数的坑（给下一次用）

1. **评测日志是 UTF-16LE**（`obs_fix_eval.log` 带 BOM）。直接 `grep "punct drop"` 是 0 命中，会误判"日志没打"。要转码再搜。
2. **`src_raw` 不是所有路径的"ASR 原文"**：`app/dual_track.py:1316-1330` 假名映射先把 `full` 换成映射文本（`うん → Yeah.`），之后才 `src_raw = full`。一旦命中，`src_raw` 存的是 "Yeah."，从 `src_raw` 看不出假名。本跑 054 没映射，所以没暴露。要修就是"映射前先存 raw"一行，不值一轮。
